## 有证据的问题

### 1. [P2] 被取消的旧音频请求会覆盖新句子的播放状态

位置：`engine/hq.js:257–281`，核心为第281行；相关第87–90、131–132、283–290行。

`startPrologueLine()` 仅保存 `current = prologue`。用户在音频尚未开始时点另一句、重播或翻页，`stopAudio()` 通过 pause/load 取消旧 `play()`，旧调用返回 false；新调用仍复用同一个 prologue 对象。旧调用随后执行 `if (!ok && prologue === current) current.playing=false`，因此把正在播放的新句标成停止。按钮显示“继续/听一听”，第一次再点不会暂停当前声音，实际声音与状态分离。底层 audioEpoch 已有保护，调用层丢失了该保护。

建议：为每次启动记录独立 request/epoch；await 后只有仍为当前请求才能更新 playing。恢复播放分支第347行也应捕获当前 prologue/player/epoch 并在 await 后比对，避免关闭或换页后恢复请求改写另一个序章状态；人物恢复分支第356行同理。

证据级别：代码可确定的异步交错；本评审未实机复现。补验：慢网开始句1后立即点句2/下一页，确认声音、暂停按钮和 `__hqState().prologue.playing` 一致；恢复播放后立即关闭序章，不应出现错误提示或旧状态写回。

### 2. [P2] HQ 没有把 engine/VERSION 传给依赖和样式

位置：`engine/hq.js:1–5`，`hq/index.html:9–14`。

外壳会按 VERSION 导入新的 `hq.js?v=…`，但其五个静态 import 都是不带版本的 URL，样式固定 `?v=5`。因此后续只升 engine/VERSION 时，新 HQ 主模块可与浏览器/CDN缓存的旧 compass/icons/badges/config 或旧CSS组合。单集引擎第6–11、19行已有按V加载依赖/CSS的方案，HQ没有继承，打破了“引擎版本只改VERSION”的约定；HQ与单集还会分别使用无版本、带版本两套共享模块缓存。

建议：HQ依赖与CSS统一从已读取的版本构造URL，内容配置/媒体映射也使用明确发布版本。本次首次加载未必触发，所以这是版本更新可靠性问题，不声称已在线上观察到旧资源。
